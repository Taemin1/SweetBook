# 하루감정 

매일 밤 오늘 있었던 일과 감정을 짧게 기록하고, 쌓인 기록을 연말에 한 권의 책으로 남기는 감정일기 서비스입니다.

- **누구를 위한 서비스인가**: 자기계발·마음챙김에 관심 있지만 거창한 다이어리 앱은 부담스러운 20대 후반 직장인. 퇴근 후 잠들기 전, 스마트폰으로 하루를 짧게(3줄 이내) 정리하고 싶은 사람.
- **주요 기능**
  - 오늘의 기록 작성 — 있었던 일 최대 3개, 감정 태그 1개(긍정 8종·부정 8종), 메모, 사진 1장, 음원 1개(모두 선택)
  - 하루 1건 제한 (같은 날 중복 작성 불가, 수정은 가능)
  - 감정일기 목록/상세/수정/삭제, 2단계 감정 필터("좋았던 하루" / "힘든 하루" → 세부 감정)
  - 상세 페이지 진입 시 첨부한 음원 자동재생
  - 연속 기록 (오늘 작성 여부 + 연속 일수)
  - 월별 캘린더 — "감정 / 사진 / 음악" 보기 모드를 드롭다운으로 전환하며 그 달의 기록을 한눈에 훑어봄
  - "감정일기 책 만들기" 주문 — 기간 선택 → 포함 일기 수 계산 → 주문 생성
  - 주문 상태 관리 (`제작 대기중 → 책 만드는 중 → 제작 완료`)
  - 운영자용 주문 관리 화면(`/admin/orders`, 사용자 화면과 분리된 레이아웃) — 상태를 드롭다운으로 자유롭게 변경, CSV 내보내기

스위트북(`api.sweetbook.com`) 같은 인쇄 API를 활용할 법한 콘텐츠 서비스라는 가정 하에, 외부 API 호출 없이 완전히 독립적으로 동작합니다.

## 실행 방법 (Docker)

```bash
# 저장소 클론
git clone <repo-url>
cd sweetbook

# 환경변수 준비
cp .env.example .env
```

`.env.example`에는 심사용 Supabase 프로젝트의 URL과 anon(공개용) key가 이미 채워져 있어, 별도 설정 없이 바로 실행할 수 있습니다.

```bash
# 실행
docker-compose up

# 접속
http://localhost:3000
```

**포트를 바꿔야 한다면** `.env`의 `PORT` 값만 바꾸고 다시 실행하면 됩니다.

```bash
# .env
PORT=4000
```

```bash
docker-compose up
# → http://localhost:4000
```

**로그인 없이** 실행 직후 더미 감정일기·주문 데이터를 바로 확인할 수 있습니다.

## 완성한 레벨

- **Lv1 (서비스 구현)** — 감정일기 작성/조회/수정/삭제, 감정 태그(긍정·부정 16종), 사진·음원 첨부, 하루 1건 제약, 감정별 목록 필터, 월별 캘린더(감정/사진/음악 보기 전환), 연속 기록
- **Lv2 (자체 주문 기능)** — 기간 선택 → 실시간 포함 일기 수 미리보기 → 주문 생성. 상태를 `pending → processing → completed`로 저장·조회·관리하며, 운영자용 `/admin/orders`에서 상태를 드롭다운으로 자유롭게 바꾸고 CSV로 내보낼 수 있음.
- **Lv3 (UI/UX 설계)** — 아래 섹션 참고

## 사용자 경험(UI/UX) 설계

**타겟 사용자**: 20대 후반 직장인. 자기계발·마음챙김에 관심 있지만 거창한 기록 앱은 부담스러워함. 평일 밤 대부분 **모바일**로(취침 전 침대에서) 짧게 기록하고, 주말엔 가끔 데스크톱으로 지난 기록을 돌아봄.

**그 사용자를 위해 내린 판단들**

| 상황                           | 판단과 이유                                                                                                                                                                 |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 첫 방문(빈 목록)               | "아직 감정일기가 없어요" + 직관적인 버튼 노출. 처음 온 사용자가 무엇을 해야 하는지 바로 알 수 있음                                                                          |
| 오늘 이미 작성함               | 홈의 텍스트가 "오늘 기록하기" 대신 "다시 보기"로 바뀜.                                                                                                                      |
| 감정을 긍정/부정 16종으로 확장 | 처음엔 "감사한 일"만 기록하는 컨셉이었지만, 힘든 날의 감정도 눌러 담지 않고 기록할 수 있어야 한다고 판단해 부정 감정 8종을 추가하고 서비스명도 하루감사 → 하루감정으로 바꿈 |
| 감정일기 필터                  | "좋았던 하루/힘든 하루"를 먼저 고르고, 그 안에서 세부 감정을 고르는 2단계 구조. 16개 감정을 한 줄에 다 늘어놓으면 오히려 못 찾아서 단계를 나눔                              |
| 캘린더 보기 모드               | "이번 달에 사진만 훑어보고 싶다" / "음악만 모아보고 싶다"는 니즈를 드롭다운 하나로 해결                                                                                     |
| 음원 자동재생                  | 일기를 열면 그날 업로드한 노래가 흘러나오게 시도                                                                                                                            |
| 연속 기록                      | 홈 상단에 크게 보여줌 — 습관형 서비스에서 동기부여가 핵심이라고 판단                                                                                                        |
| 주문 상태                      | 진행 바 형태로 시각화                                                                                                                                                       |
| 로딩                           | 레이아웃이 흔들리지 않도록 스켈레톤 UI 활용                                                                                                                                 |
| 화면 크기                      | 콘텐츠 폭을 모바일 화면에 가깝게 제한해 데스크톱에서도 모바일과 비슷하게 보이게 함 — "넓게 쓰기"보다 "짧게 쓰기"가 이 서비스에 어울린다고 판단                              |
| 관리자 화면                    | `/admin/orders`는 소비자용 내비게이션 없이 별도 레이아웃(더 넓은 컨테이너) 사용 — 운영자 도구와 일반 사용자 화면은 목적이 다르다고 판단해 완전히 분리                       |

**의도적으로 넣지 않은 것**

- 회원가입/로그인 — 단일 사용자 가정이고, 심사자가 로그인 없이 즉시 확인해야 한다는 요구사항
- 결제/배송/실제 인쇄 — 과제 요구사항에서 Lv2 범위 밖으로 명시됨
- 사진·음원 여러 개 첨부(앨범형) — 일기 1건당 각각 1개까지만 허용. "짧고 가벼운 기록"이라는 컨셉을 지키기 위해 다중 업로드·갤러리 UI는 넣지 않음
- 멜론/Spotify 같은 음악 스트리밍 서비스 연동 — 멜론은 외부 개발자용 임베드·재생 API 자체가 없고, Spotify 등도 전곡 재생엔 사용자의 유료 구독 로그인이 필요해 개인 프로젝트 범위를 벗어난다고 판단. 대신 사용자가 직접 가진 음원 파일을 업로드하는 방식으로 구현

## 기술 스택 및 아키텍처

| 영역           | 선택                                | 이유                                                                                                                                                                            |
| -------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 프레임워크     | Next.js 16 (App Router, TypeScript) | 프론트+백엔드를 한 프로젝트에서 처리해 Docker 컨테이너 1개로 배포 가능, 구조가 간단하기 때문에 별도 백엔드까지 구성할 필요까지는 없다고 판단, 가장 많이 다뤄본 기술 스택을 선택 |
| 스타일         | Tailwind CSS v4                     | 기성 유틸리티로 빠르게 구현. 디자인 감각보다 UX 판단이 중요한 과제라 커스텀 디자인 시스템을 따로 만들지 않음                                                                    |
| DB / 파일 저장 | Supabase                            | `@supabase/supabase-js`로 서버에서 직접 CRUD·파일 업로드, 별도 백엔드 서버 불필요, Next.js와 함께 사용하기 쉬움                                                                 |
| 배포           | Docker                              | `docker-compose up` 1회 실행 요구사항 충족                                                                                                                                      |

```
src/
├── app/
│   ├── (app)/            # 사용자 화면 — 홈 / entries / calendar / orders (공통 NavBar 레이아웃)
│   ├── admin/             # 운영자 화면 — orders (별도 레이아웃, NavBar 없음)
│   └── api/                # entries/count(실시간 미리보기), orders/export(CSV)
├── components/            # EntryForm, CalendarGrid, AudioPlayer, 뱃지류 등
└── lib/                   # Supabase 클라이언트, 데이터 접근 함수, 타입, 유틸
```

## 설계 의도

- **왜 이 아이디어를 선택했는가**: "콘텐츠가 본체, 책은 부가 기능"이라는 구조에 가장 자연스럽게 맞는 게 꾸준히 쌓이는 개인 기록이라고 생각했습니다. 감정일기는 매일 짧게 쓰는 습관형 콘텐츠라 부담 없이 작성할 수 있고, 1년치가 쌓이면 "책으로 남기고 싶다"는 동기가 실제로 존재하는 카테고리라고 판단했습니다. 처음엔 긍정적인 감정만 다루는 "감사일기"로 시작했지만, 만들다 보니 힘든 날의 감정도 담을 수 있어야 한다는 생각이 들어 감정 태그를 긍정·부정 16종으로 넓히고 서비스명도 "하루감정"으로 변경했습니다.
- **사업적 가능성**: 커플/가족이 함께 쓰는 공유형 감정일기, 회사 팀 단위의 감사 인정 문화 서비스로도 확장할 여지가 있다고 생각합니다.
- **더 시간이 있었다면**: 감정 통계 시각화, 실제 주문 결제 연동, 여러 사용자를 위한 로그인/개인화, 개인화를 통한 비밀 일기 및 '펑' 일기, Spotify API를 통한 앨범 사진 등 음악 정보 연동
